# printdrop 動作確認マニュアル

このマニュアルは、printdrop(フォルダ監視型 PDF 印刷ジョブ送信アプリ)の動作確認を、実際のプリンターを使って行うための手順書です。上から順に実施してください。

**所要時間の目安**: 約 20〜30 分
**必要なもの**:

- 作業用 PC(Windows / macOS / Linux いずれも可)
- ネットワーク接続されたプリンター(複合機)と、その **IP アドレス**
- テスト印刷用の PDF ファイル 1〜2 個(1〜2 ページ程度の軽いもの)

各ステップの最後に ✅ **合格基準** を記載しています。満たさない場合は、先へ進まず「7. うまくいかないとき」を参照してください。

---

## 1. 事前準備 — Python の確認

ターミナル(Windows は PowerShell、macOS は「ターミナル」)を開き、次を実行します。

```bash
python --version
```

> Windows で `python` が見つからない場合は `py --version`、macOS/Linux では `python3 --version` を試してください。以降のコマンドの `python` も同じものに読み替えます。

✅ **合格基準**: `Python 3.9` 以上のバージョンが表示される。
表示されない場合は https://www.python.org/downloads/ からインストールしてください(追加ライブラリのインストールは不要です)。

## 2. コードの取得と自動テスト

まずプリンターを使わずに、プログラム自体が正常かを確認します。

```bash
git clone <このリポジトリのURL> Menu-Flyer
cd Menu-Flyer
git checkout claude/pdf-printing-job-app-o4rg6y
python -m unittest discover -s tests -v
```

✅ **合格基準**: 最後に `Ran 12 tests` と `OK` が表示される。
ここで失敗する場合はプリンター以前の問題なので、エラー全文を控えて開発者(Claude)に共有してください。

## 3. プリンターの情報を調べる

### 3-1. IP アドレスの確認

プリンター本体のパネルで「メニュー」→「ネットワーク設定(または機器情報)」を開くか、ネットワーク設定リストを印刷して、IP アドレス(例: `192.168.1.50`)を控えます。

### 3-2. Web 管理画面で IPP が有効か確認

PC のブラウザで `http://<プリンターのIPアドレス>` を開きます。

- 管理画面が表示される → ネットワーク疎通 OK
- ネットワーク設定の中に「IPP」の項目があれば、**有効** になっているか確認(無効なら有効にする)

✅ **合格基準**: ブラウザでプリンターの管理画面が開ける。
開けない場合は、PC とプリンターが同じネットワークにいるか、IP アドレスが正しいかを確認してください。

## 4. アプリの設定と接続確認

### 4-1. 設定ファイルの作成

リポジトリのフォルダ内で:

```bash
python -m printdrop --init
```

`config.json` が作成されます。

### 4-2. printer_uri の設定

`config.json` をメモ帳等で開き、`printer_uri` を自分のプリンターに書き換えて保存します。

```json
"printer_uri": "ipp://192.168.1.50:631/ipp/print",
```

> IP アドレス部分を 3-1 で控えたものに置き換えてください。パスは機種により異なります。まず `/ipp/print` を試し、ダメなら次の順で試します:
> `/printer`(RICOH 系)→ `/ipp`(EPSON / brother 等)→ `/ipp/lp`

### 4-3. 接続確認

```bash
python -m printdrop --check
```

✅ **合格基準**: 次のようにプリンター名・機種名が表示される。

```
プリンターに接続できました: RICOH IM C3000 / RICOH IM C3000 PDF / 状態: idle (待機中)
```

`接続に失敗しました` と出る場合は、4-2 の別パスを順に試してください。全パスで失敗する場合は「7. うまくいかないとき」へ。

## 5. テスト送信(1 件だけ) — 最重要ステップ

このステップで「**ジョブがプリンターに保存(保留)されるか**」を確認します。

### 5-1. 送信

テスト用 PDF を用意して:

```bash
python -m printdrop --once test.pdf
```

✅ **合格基準 A**: `送信完了: test.pdf -> ジョブ ID 123` のように表示される。

### 5-2. プリンター側でジョブを確認

プリンターの操作パネルで保留ジョブを探します。メニュー名はメーカーにより異なります:

| メーカー | 探す場所(例) |
|---|---|
| RICOH | 「プリンター」→「保留文書 / 蓄積文書」 |
| Canon | 「プリント」→「ホールド / 留め置き」 |
| 富士フイルムBI | 「ジョブ確認」→「セキュリティープリント / 保存文書」 |
| 京セラ | 「ジョブボックス」→「保留」 |
| その他 | 「ジョブ一覧」「保留ジョブ」等 |

ジョブは `config.json` の `requesting_user_name` の名前(初期値: `menu-flyer`)で表示されます。

✅ **合格基準 B**: パネルに `test.pdf` のジョブが **印刷されずに** 保留されている。

### 5-3. 印刷の実行(リリース)

パネルでそのジョブを選択し、「印刷 / 実行」します。

✅ **合格基準 C**: PDF が正しく印刷される。

> **⚠️ 判定の分かれ目**
>
> - **A・B・C すべて OK** → 期待どおり。次の 6 へ。
> - **A は OK だが、保留されず即印刷された** → その機種は保留機能(`job-hold-until`)に未対応です。運用上「即印刷で良い」ならこのまま使えます。「保存が必須」なら **機種名(例: RICOH IM C3000)を控えて開発者に連絡** してください。機種固有の蓄積印刷属性で対応します。
> - **A で失敗**(`document-format-not-supported` 等)→ 「7. うまくいかないとき」へ。

## 6. フォルダ監視の通し確認(本番と同じ使い方)

### 6-1. 監視を開始

```bash
python -m printdrop
```

`フォルダ監視を開始します: .../inbox` と表示され、動き続けます(この画面は開いたままにする)。

### 6-2. PDF を投げ込む

エクスプローラー / Finder で、リポジトリ内にできた `inbox` フォルダにテスト PDF を **コピー** します(移動でも可)。

✅ **合格基準**: 5〜10 秒以内に画面に次が表示され、

```
PDF を検出しました: test2.pdf
送信完了: test2.pdf -> ジョブ ID 124 (プリンター側に保留中) / 移動先: .../sent/test2.pdf
```

- `inbox` フォルダが空になり、`sent` フォルダに PDF が移動している
- プリンターのパネルに新しい保留ジョブが増えている

### 6-3. 連続投入の確認(任意)

PDF を 2〜3 個まとめて `inbox` に入れ、すべて順に送信・移動されることを確認します。

### 6-4. 異常系の確認(任意)

プリンターの電源を切った状態で PDF を `inbox` に入れると、リトライ(3 回)のログの後、PDF が `error` フォルダへ移動すれば正常です。確認後はプリンターの電源を戻してください。

### 6-5. 停止

監視画面で `Ctrl + C` を押して停止します。

## 7. うまくいかないとき

| 症状 | 確認・対処 |
|---|---|
| `--check` が全パスで失敗 | ① PC から `ping <プリンターIP>` が通るか ② プリンター管理画面で IPP(ポート 631)が有効か ③ 社内ネットワークのファイアウォールで 631 番ポートが遮断されていないか |
| `client-error-document-format-not-supported` | 機種が PDF 直接印刷に未対応(古い機種・家庭用に多い)。機種名を控えて開発者に連絡 |
| 保留されず即印刷される | 機種が保留機能未対応。5-3 の「判定の分かれ目」参照 |
| パネルにジョブが見つからない | 別のメニュー名の可能性。プリンターの取扱説明書で「蓄積」「ホールド」「保留」を検索 |
| `inbox` に入れても反応がない | ① 拡張子が `.pdf` か(大文字 `.PDF` は OK、`.pdf.txt` 等は NG) ② 監視が起動中か ③ `-v` を付けて起動し詳細ログを確認 |
| 文字化けする / エラー全文を報告したい | 実行したコマンドと画面出力をそのままコピーして開発者に共有 |
